## Overall impression

The visualization in `11.png` looks physically plausible: zonal (east-west) flow bands, some meridional structure, and emergent eddies on a rotating sphere. The color mapping and streamline rendering are coherent. The codebase is well-organized (grid generation, dynamics, coupling, particles, rendering are cleanly separated).

---

## Simulation problems I found

### 1. Air–ocean momentum coupling is physically wrong (major)

In `shader.js` (`COUPLE_FS`):

```glsl
vec2 rel = vl - vt;
vec2 dstress = uWindStress*uDt*rel*(1.0-land);
vt += dstress;
vl -= dstress*0.02;
```

The ocean gains the full `dstress`, but the air only loses `0.02 * dstress`.  
Physically, momentum transfer should be reciprocal: the air deceleration should be larger than the ocean acceleration by roughly the density-depth ratio `(ρ_water·H_water)/(ρ_air·H_air) ≈ 40–1000`, not smaller by a factor of 50. As written, **~98% of the momentum vanishes** from the system. This will cause the ocean to spin up unrealistically and the wind field to be weakly damped by the ocean.

### 2. No true mass conservation / diagnosed pressure (major design limitation)

Pressure is never dynamically evolved. In `stepAir`:

```glsl
outA = vec4(v1, tr1.x, p0);   // p0 = a0.w (pressure just copied)
```

Pressure is purely diagnostic (`Pl = 101325 - 60·(Tl-288) + 25·(Th-250)`). The velocity field is corrected with a simple `v0*div` term, but there is **no pressure-Poisson solve**. Over long runs this allows mass sources/sinks to accumulate, so the wind field can slowly drift.

### 3. Seam in equirectangular projection (visual bug)

`uLookup` is created with `CLAMP_TO_EDGE` in both S and T directions (`engine.js` `mkTex`). In equirectangular mode the S direction corresponds to longitude, so the date-line seam is not wrapped:

```javascript
gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_WRAP_S, gl.CLAMP_TO_EDGE);
```

It should use `gl.REPEAT` for S (longitude) while keeping `CLAMP_TO_EDGE` for T (latitude).

### 4. Particle respawn opacity discontinuity (minor visual bug)

In `PART_FS`:

```glsl
if(age <= 0.0){
  ...
  age = 1.0 + hash11(float(pid)+uSeed)*0.5;
}
```

and in `PART_VS`:

```glsl
vA = clamp(p.w,0.0,1.0) * clamp(1.5 - abs(p.w-0.5)*2.0, 0.0, 1.0);
```

Respawned particles start at age `1.0–1.5`, which always yields `vA ≈ 0.5` instead of fading in from 0. You see sudden half-opacity dots appearing.

### 5. First-order upwind advection (modeling limitation)

Both temperature and momentum use:

```glsl
float w = un > 0.0 ? 0.0 : 1.0;
advT += L*un*mix(tr0, trj, w);
```

This is first-order upwind, which is **excessively diffusive** for sharp gradients (fronts, jets). It smears temperature and velocity structures over time. Acceptable for a fast GPU climate toy, but it limits realism.

### 6. Hardcoded ocean density in the ocean shader

```glsl
vec2 acc = -gradP/1027.0 + uNuVel*lapV - advV + v0*div;
```

`1027.0` is buried in the shader source rather than passed as a uniform. If you ever want to simulate a different planet (e.g., freshwater ocean, or a gas-giant "sea"), you have to edit GLSL source.

## What looks good

- **Coriolis**: The implementation (`-2·Ω×v` projected onto local east/north) is mathematically correct for the chosen north-pole axis.
- **Dual-hex grid**: Neighbor indexing, area computation, and local frames (`e1`, `e2`) are handled correctly, including the 12 pentagonal vertices.
- **Thermodynamic coupling**: Sensible/latent heat, radiation, convection, cloud/rain parameterization, and thermohaline mixing are all internally consistent and produce emergent Hadley-like behavior.
- **Rendering pipeline**: Double-buffered A/B state, correct ping-pong through `dynO → dynA → cplO/cplA`, and particle trail geometry are all sound.
- **Stability**: CFL for the chosen `dt=300 s` and grid spacing (~250 km at L5) is comfortable; viscosity terms further damp high-frequency noise.

---

## Verdict

**Visually**: the result in `11.png` looks good — the streamlines and temperature field are coherent and Earth-like.

**Physics-wise**: the most serious issue is the **air–ocean momentum coupling being off by two orders of magnitude and in the wrong direction** (point #1). The diagnosed-pressure / no-Poisson-solve approach (#2) is the second biggest limitation. The equirectangular seam (#3) is a clear rendering bug if you use map view.
