frame ms = full frame (physics substeps + flow update + draw), draw ms = draw only (globe + tracers, no stepping). max fps is compute-limited; on a vsync display the GUI still caps at your refresh rate (typically 60). “sub@60” intuition: any config whose frame ms is under ~16.7 runs at a smooth 60. Explicit is the cheaper ocean integrator; implicit adds the Jacobi free-surface solve. Higher level ≈ 4× the cells per step; higher particle count scales the tracer draw.
days/s = substeps × dt × fps / 86400 (P2.3; auto rows cap fps at 60 for the vsync-delivered rate).
tracers ms (P3.1) = flow update (smooth+vflow+flow) + tracer draw (render on−off); the @Bk column repeats it at the second particle count (pool rebuild between). auto→N rows (P2.2) fit frame(subs) through the measured substeps points and pick the largest N with frame ≤ 16.7 ms.

No number on this page rests on a sub-tick timer delta. Chrome ≥ 91 clamps performance.now() to 0.1 ms on any page that is not cross-origin isolated — a file:// page never is — and Firefox/Safari clamp to 1 ms there. So the old single-shot sample (t0; frame(); finish(); t1) quantized everything under a tick to 0.00/0.10 ms: the archived 30-03 draw column read 0.00 at every level and its ×10 rows read 0.10 ms where the ×128 slope says 1.5–3.4 ms. Every measurement here is instead a batch: N calls, one gl.finish(), value = span/N, with N grown until the batch spans ≥ 100 timer ticks (≤ 1 % quantization error) — the same trick the backend bench uses. Batching also keeps the GPU queue full, so a driver whose finish() returns early for tiny batches can no longer under-report a ×10 row by 10×. n/batch is the N used; # timer in the copied log is the measured resolution. If a value is still printed as <res the batch could not be grown enough to resolve it — read it as a ceiling, never as a magnitude.
A * on a value means its batch hit the n cap before spanning the target, so its error bar is wider than 1 % (the copied log counts them).
Runs repeats the whole matrix and reports each cell's median — plan rule 3 (“L6 within 2 % of the committed baseline”) needs median-of-3, single runs vary ±5–8 %.
When a run ends the page stops all simulation work: the planet is disposed and the GL context is dropped, so the GPU process can't keep burning CPU on queued frames (the canvas goes blank on purpose). The copied report keeps the device strings captured at start; press Run benchmark to rebuild and measure again.
